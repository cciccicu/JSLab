# UI 性能与验证

所有脚本共用 UI v2。组件数量、布局深度和二维码数量没有额外硬上限；运行契约中的数量建议用于小屏设备的首屏预算，实际承载能力受内容、刷新频率和固件影响。接口见 [UI 参考](../reference/ui-api.md)。

## 编写与维护界面

给动态重排的组件设置稳定且唯一的 ID。同一轮同步执行中的 signal 更新会合并；相同值或同一对象引用不会触发刷新。渲染函数保持纯粹，不在其中改变 signal 或调用刷新。

布局编译器缓存叶子测量，并复用相同显示结果；发布器保留稳定节点，只写变化字段。缓存、回调与页面响应式数据分离。详细的数据流与边界见[运行器原理](../guide/how-jslab-works.md)。

## 主机验证

图片与 Canvas 共用会话图片资源层。Canvas 像素采用 RGBA8，绘图方法和缓冲不进入 ViewModel，只有提交后的 URI、尺寸与 fit 进入显示节点。`submit()` 同步编码调用时的像素、异步写入文件；普通 UI 刷新不进行编码。首版 PNG 使用无压缩 DEFLATE 块，避免引入完整压缩库；编码器是独立模块，后续可在保持公开方法及提交语义的前提下替换。文件大小约为像素数乘 4 加少量头部，实际设备的加载耗时和内存需单独测量。

手环画布建议从 `pixelWidth:160, pixelHeight:96` 开始，按需提交；`width/height` 独立控制布局，内置示例用 `width:'100%'` 等比例铺满父容器。显示缩放不会改变像素分辨率或触发编码；旧脚本省略 pixel 参数时保留原有尺寸语义。清屏用 32 位像素批量填充，并保持未改变像素时不增加提交版本；直线只扫描主轴附近的窄带，保留原距离判定、端点和透明混合结果。PNG 写入与 Adler/CRC 校验合并成一次像素遍历，Adler 在行片段结束时取模，输出仍是相同的 RGBA8 PNG。内置“图片与 Canvas”模板保留首次自动绘制，并显示绘图与提交的实测毫秒数；提交耗时含编码和文件写入，不含原生图片加载完成。

新增资源型组件时，扩展 `uiMedia` 描述解析器和原生模板中的对应分支，布局编译器缓存基本显示字段；未知类型返回明确错误。新组件通过 `jslabVersion` 选择对应提示词，旧版提示词快照保持原有接口说明。

在 `vela-quickapp/` 运行 `npm run test:runtime`，覆盖节点增删重排、稳定身份、失败恢复、回调更新和旧脚本。`tests/fixtures/` 中的历史编译器与脚本是兼容性测试基准。

## 设备验证

[人工运行器验收脚本](../../examples/diagnostics/unified-runner-check.js)用于检查视图切换、重载与对话框。Node.js 测量逻辑计算耗时；在目标设备上测量原生布局、绘制、触摸响应和整体帧率。
