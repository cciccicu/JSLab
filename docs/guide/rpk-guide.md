# 导出为独立应用

> 版本要求：导出功能由 JSLab Cloud 2.0.3 及以上提供，无需安装设备端。独立应用的 API 取决于导出时使用的引擎；图片和 Canvas 需要包含 JSLab 2.0.7 API 的引擎，更新设备端不会更新已导出的应用。

RPK 是安装到手环或手表上的快应用安装包。云空间可以把一个脚本和 JSLab 脚本引擎一起打包，让它从设备应用列表直接启动，无需先安装或打开 JSLab。

## 打包前准备

1. 在目标设备上运行脚本，确认主要功能正常。
2. 将最终代码保存到 [云空间](https://ccicc.icu/jslab-cloud/workspace)。打包使用已保存的云端版本，不使用网页编辑窗口中尚未保存的文字。
3. 确认云空间已激活，JSLab 额度足够。当前每次成功打包扣除 ¥0.10。

## 填写信息并下载安装包

1. 在云空间文件旁点击“打包为 RPK”。打包使用当前已保存的云端源码。
2. 选择目标设备（小米手环 Pro 或 REDMI Watch 5），填写应用名称、包名（如 `com.example.myapp`）、版本号、正整数 versionCode 和作者。
3. 可上传 PNG 图标（不超过 32 KiB、512×512），选择禁用 console 或隐藏顶栏。
4. 首次可点击“在线生成签名”，生成后自动应用；之后直接选择已保存的签名 ZIP，无需解压。不填写时使用固定的 JSLab 共享默认签名。
5. 点击“打包”，成功后点击“下载”保存独立安装包。下载可重复点击，不会再次打包或扣费；修改打包信息后需要重新打包。新生成的签名可通过“下载签名 ZIP”保存。

每次成功打包扣除 ¥0.10 **JSLab 额度**，与 AI 生成代码共享余额。失败不扣费；
对相同请求的网络重试不会重复扣费。再次使用相同表单下载相同结果也不会重复扣费；
修改打包信息或重新打开弹窗会发起新请求。

保留签名以便下次更新同一应用：下载 ZIP 并妥善保存，下次直接上传该 ZIP。
使用手机通信的脚本需要与手机端使用相同的签名。RPK 包内脚本资源可被解包读取，禁用 console 不提供代码加密。

RPK 自带 JSLab 脚本引擎，无需设备上预先安装 JSLab；存储数据属于新应用自己的沙箱。
未隐藏顶栏时，右上角信息按钮打开关于页，展示作者、版本、“由 JSLab Cloud 生成”
及“使用 JSLab 脚本引擎运行”。

## 应用名称、包名和签名有什么区别

| 项目 | 用途 |
| --- | --- |
| 应用名称 | 显示在设备应用列表中的名字 |
| 包名 | 应用的固定身份，例如 `com.example.counter`；更新同一个应用时保持一致 |
| 版本号与 versionCode | 标记此次更新；versionCode 使用正整数 |
| 签名 | 用于识别更新是否来自同一发布者；后续更新使用同一份签名 |

要继续更新同一应用，请保存包名和签名 ZIP。使用不同签名通常不能直接覆盖原安装。不要为了绕过签名问题而卸载有重要记录的旧应用，先做好数据备份。

## 安装、验证与更新

使用支持目标设备的安装工具安装下载的 `.rpk`，然后从设备应用列表打开。分别检查启动、按钮、保存记录和返回行为。页面布局与系统能力依然受设备型号影响，应选择正确的打包目标。

独立应用拥有自己的存储。JSLab 中已有的脚本记录不会自动复制过去，云端重新打包也不会把设备上的记录带入安装包。

以后修改脚本时，保存新的云端代码，保留原包名和签名，再次打包。只想分享源码而不制作安装包，可以使用 [JS 市场](market-guide.md)。
