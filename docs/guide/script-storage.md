# 保存数据与设置

> 最低支持版本：`script.data`、`script.config` 及其全部方法支持 JSLab 2.0.0 及以上。通过同步器编辑或导出数据需要设备端 2.0.4 及以上，并配合支持脚本数据同步的配套端。

脚本中的普通变量只属于这一次运行。重新运行后还需要保留的内容，可以写入 `script.data`；用户偏好可以写入 `script.config`。它们的用法相同，但各自保存，不会相互覆盖。

## 记住上次运行的结果

普通变量在程序重新运行时会重新创建。希望下次还能读到的内容，可以放进 `script.data`：

```js
async function main() {
  const previous = await script.data.get('opens', 0);
  const current = previous + 1;
  await script.data.set('opens', current);
  console.log('这是你第 ' + current + ' 次打开这个脚本。');
}

return main();
```

第一次运行时还没有 `opens`，所以 `get('opens', 0)` 返回默认值 0。之后每次运行，都会读出上次保存的数字，再加一保存。

`script.config` 的用法相同，适合保存字号、默认数量等设置。你可以把程序产生的记录放进 `data`，把用户选择的偏好放进 `config`。

| 操作 | 用法 |
| --- | --- |
| 读取内容，没有时使用默认值 | `await script.data.get('key', 默认值)` |
| 保存文字、数字、数组或普通对象 | `await script.data.set('key', 内容)` |
| 删除一项 | `await script.data.delete('key')` |
| 删除本脚本保存的全部数据 | `await script.data.clear()` |
| 读取本脚本保存的全部数据 | `await script.data.all()` |

每个脚本有自己的数据，互不混用。通过 JSLab 重命名文件时，数据会一起迁移；删除脚本时，对应的数据和设置也会删除。单项内容及 `data`、`config` 存储区不设固定字节上限，实际容量受设备内存和可用存储空间影响。

取消存储区固定容量上限需要 2.0.4；较旧版本仍有容量限制。方法名和调用方式保持相同。

## 适合保存哪些内容

可以保存文字、有限数字、布尔值、数组和普通对象等可以用 JSON 表达的内容。不要保存函数、循环引用或需要依赖原型才能工作的实例；日期可以先转成字符串。

这些方法返回 Promise。依赖保存结果的下一步操作应在 `await` 之后进行，并在失败时保留用户输入。不要每收到一次高频传感器回调就写入存储，先在内存中整理，再在有意义的时机保存。

## 文件名决定记录属于谁

| 操作 | 对记录的影响 |
| --- | --- |
| 修改原文件的源码 | 原文件名不变，已有数据和配置保留 |
| 通过 JSLab 或同步器重命名 | 数据和配置迁移到新文件名 |
| 另存为新的文件名 | 新名字按另一个脚本使用，不自动继承原记录 |
| 删除脚本 | 同时清除对应的数据和配置 |
| 在另一台设备运行同名文件 | 不会自动取得原设备的数据 |

文件名隔离是为了方便管理，不是安全沙箱。脚本还可以通过文件接口访问 JSLab 应用内的文件，因此只运行你信任的代码。

## 清除、导出和恢复

在设备编辑器菜单可分别清除当前脚本的数据和配置。需要查看或备份内容时，新版 [Android 同步器和 AstroBox 插件](sync-guide.md) 提供数据编辑、读取和 JSON 导出。

只上传或下载 `.js` 源码不会同时复制记录。保存备份时同时保留源码和数据 JSON，并记录它们对应的文件名。导出为独立应用后，数据属于新应用的存储，也不会自动从 JSLab 复制过去。

如果需要保存文本文件或二进制文件，而不是按键保存记录，继续阅读 [读写与管理文件](files.md)。
