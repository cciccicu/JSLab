# 常见问题与排查

本页覆盖不同版本的常见问题。先按[最低支持版本说明](installation.md)核对功能要求；早期功能以 JSLab 2.0.0 为基线，新增功能以对应文档中的版本为准。

先确认问题发生在哪一步：本地编辑、运行脚本、连接配套端，还是访问云服务。下面的处理顺序尽量保留已有代码和数据。

## 代码或文件没有更新

| 看到的情况 | 先检查什么 |
| --- | --- |
| 刚才运行正常，重新打开却是旧代码 | 运行不会自动保存，检查编辑器是否已经保存 |
| 网页保存了，设备仍是旧内容 | 在设备云空间刷新后重新下载，并确认覆盖目标 |
| 设备改了，网页没有变化 | 保存本地文件后，还需要主动上传到云空间 |
| 同步器显示了新内容，设备运行仍不对 | 确认保存成功、连接的是目标设备，运行的是同名目标文件 |
| 云文件修改了，市场作品仍是旧版本 | 在“我的发布”修改作品并重新提交，等待审核通过 |

如果两边都存在需要保留的修改，先导出或另存为副本，再选择覆盖方向。云空间没有历史版本或回收站。

## 云服务连接失败

1. 在设备“设置 > 传输方式”检查选择的是 fetch 直连还是 JSLabSync 网络桥接。
2. 使用桥接时，保持配套端打开、设备连接正常，并确认云转发没有关闭。
3. 社区版检查“云账户”中的服务器地址，确认网页登录的也是同一服务器。
4. 在手机浏览器打开该服务器，确认服务本身可访问，然后重试设备请求。

网页可访问并不能保证设备直连也可用。反过来，云服务能通过桥接访问，也不表示用户脚本的原生网络请求会通过手机转发。详见 [同步与网络桥接](sync-guide.md)。

## 配对或授权失败

配对码过期时，在设备重新生成。网页确认后保持设备在线，直到设备也显示配对完成；只完成网页确认，设备仍可能没有拿到授权。

提示设备授权失效时，重新发起配对。在网页“设备管理”撤销授权后，设备不能继续使用原授权访问账户。更换服务器也需要在新服务器重新配对。

云空间“未激活”与“未配对”是不同状态。前者在网页“充值与激活”处理，后者从设备云账户页发起。详见 [云账户与云空间](cloud-guide.md)。

## 同步器一直等待连接

Android 同步器先检查小米运动健康是否连接设备，是否已授予设备管理权限。保持设备端 JSLab 打开，再点击“重试握手”。AstroBox 插件则检查 AstroBox 中的当前设备和插件连接状态。

自行编译或更换来源后才出现的问题，还应核对 Android 与设备端安装包的包名和签名。先保留设备里的脚本，不要反复卸载应用来尝试解决。

## 大脚本或编辑器显示异常

超过 48 KiB 时，设备打开编辑器前的提醒允许选择“继续编辑”，不是源码长度硬限制。当前同步器也不另设这个源码上限；仍被旧插件拒绝时，请从 [发布仓库](https://github.com/cciccicu/JSLab-AstroBox-Plugin-Release) 更新 JSLab Sync。

大文件编辑卡顿时，先保存或备份，再用手机、电脑编辑。语法高亮的字符和行数阈值只影响显示处理，调高阈值不会让设备获得更多内存。字体更换尚未开放，入口显示“即将上线”属于当前版本行为。

## 脚本没有显示预期界面

基础 UI 支持 2.0.0 及以上，`ui.getWidth()` 需要 2.0.4，图片与 Canvas 需要 2.0.7。提示未知组件或方法不存在时，优先检查客户端是否过老；独立应用需用新版引擎重新导出。

先按返回查看日志。只有调用 `ui.render()` 才会显示脚本界面；只调用 `console.log()` 的脚本会留在日志页。

出现错误时检查括号、引号、重复的组件 ID 和过窄的布局。界面生成函数里反复修改状态或发起请求，可能造成持续刷新。同步死循环会阻塞脚本执行，应在代码中给循环设置结束条件。

需要示例时查看 [第一次使用](getting-started.md) 和 [制作交互界面](ui-api.md)。

## 某个设备接口无法使用

不同型号和系统版本的能力不同。先使用 `script.canUse()` 查询，再处理失败回调；能力检查通过也不保证授权、网络或当时的设备状态满足要求。

原生接口名称和 JSLab 脚本名称有时不同。例如能力检查使用 `@system.file.readText`，实际脚本调用 `system.files.readText()`。不要照搬官方文档中的模块导入。对应关系见 [设备接口使用说明](system-api.md)。

## AI 或独立应用打包失败

先检查账户是否激活、额度是否足够。AI 提示版本不兼容时，更新设备端；自建服务器还需由管理员检查服务版本。打包失败时核对目标设备、应用信息、图标和签名格式，并保留错误提示。

生成的独立应用没有原来的记录是正常情况：它使用自己的存储，不会自动继承 JSLab 中的脚本数据。详见 [AI 使用指南](ai-guide.md) 和 [独立应用导出指南](rpk-guide.md)。

## 反馈问题时带上这些信息

说明设备型号、JSLab 和配套端版本、出错页面、操作步骤、完整错误提示，以及使用的服务器和传输方式。脚本问题尽量提供能复现的最小代码，并去掉账号、令牌和私人数据。
