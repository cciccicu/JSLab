# Vela 快应用协作约束

本目录是 Vela 原生快应用，遵守根目录的修改范围、兼容性和设备授权要求。开发说明集中在 [快应用开发](../docs/development/quickapp.md)、[设备布局](../docs/development/device-layouts.md)和[模块边界](../docs/development/quickapp-modules.md)。

## 设备与行为

- 默认 Pro 布局为 336×480 / designWidth 336；RW 为 432×514 / designWidth 432，在构建期选择。
- `src/` 保存默认布局，`targets/redmi-watch5/` 提供静态覆盖。共用组件、模板、事件和业务逻辑，只通过尺寸、坐标与样式适配设备。
- 同一功能不得为不同设备创建不必要的独立流程、占位组件或隐藏条件。确有平台限制需要差异时，先说明并取得明确指示。
- 只修改用户要求的功能及其直接依赖；适配、检查和打包不授权额外修复或重构。只要求打包时不得改变源码行为。
- 保留旧脚本 API、参数、返回值、数据格式和设备云接口。新增能力采用兼容扩展，并验证旧调用者。

## Vela 实现

- 普通 `.ux` 页面只有一个模板根节点，使用 Vela 原生组件和 CSS 子集；应用入口可只有 script。
- 文字使用 text / span，列表使用稳定 tid，条件节点相邻；保持项目已有 @import 样式方式。
- Pro / RW 共享结构的修改必须检查对应样式，不在内联样式中写死设备位置。
- 页面只持有显示状态。跨页面有状态服务由 app.ux 持有，通过 `$app.$def` 访问；函数、缓存和大文本缓冲避免进入响应式数据。
- 在适当生命周期停止定时器、订阅和监听，避免退出后更新页面。

## 构建与验证

- 未明确要求发布升级时，不递增 manifest、package.json 或锁文件版本。
- `npm run check:devices` 验证设备覆盖和几何边界。共享布局改动按影响检查两个构建目标。
- 非测试类任务不要新增测试。只验证本次修改涉及的部分，不为覆盖率运行无关项目或扩大测试范围。
- 构建、测试和打包不能自动连接模拟器或设备。start、watch、ADB 和设备部署需要单独明确授权。
- AIoT release 会清空 dist；需要的产物放在该目录之外。隔离构建入口将产物保存到 release-archive。
- 不在项目中复制含 .ux 的备份源码树，工具链可能扫描到备份资源。临时副本使用项目外的受控目录。
- 运行引擎改变后，从主项目同步并重建独立 RPK 模板，不直接修补模板生成文件。
