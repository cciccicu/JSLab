# 对话框与捐助二维码回归修复

实机反馈：对话框布局坍缩、打开后立即返回、再次调用报 DIALOG_BUSY；捐助二维码尺寸被改错。
前轮静态检查和构建成功没有验证跨页面模块共享与实际样式编译，相关结论已更正。

## 根因与修复

1. **请求状态跨包失效。** 原安装包的 app、confirm、run 字节码均包含 DIALOG_BUSY，
   dialogState 的模块变量分别存在于各入口包中。overlay 读取的是自己的空副本，onReady 返回；
   应用请求没有结算，因而永久占用。现在只有 app.ux 引入 dialogState，全部 15 个来源/overlay
   页面通过 `$app.$def` 调用同一组方法。原生路由仅传 dialogId，protected 字段接收并核对请求；
   无效页面先取消匹配的请求再返回，旧页面无法结算新请求。
2. **样式导入被工具链忽略。** Vela 文档允许 `<style src>`，但项目实际使用的 toolkit 2.0.5
   解析器只解析 style 正文，没有读取 src。实际解析确认 confirm/select/text-input 均为 0 条规则，
   number-input 的 @import 则正常。四页统一使用 @import，当前均得到 35 条合并后的样式规则，
   根布局为 336×480，顶栏按钮为绝对定位的 72px，数字页仍正确覆盖输入卡高度为 102px。
3. **二维码无证据的尺寸改动。** 撤销 payment-qrcode 类、220×220 尺寸和二维码父容器新增的
   align-items，按修改前源码恢复原生默认尺寸行为。欢迎文字恢复原行高及单行显示；保留分钟时钟
   生命周期、顶栏层级和普通内容区留白的修改。

## 范围与验证

公开的 dialog API、action/value 结果、UI/Console 切换、输入校验和日志行为不变。
请求与函数仍在普通 JS 中；没有增加响应式请求对象、全局路由栈、手势代理或轮询。
各页的输入/选项缓冲仍为页内 WeakMap，只有应用级请求集中在 app.ux 的单一模块实例。
没有改持久化键、配置格式、云接口或云插件，应用仍为 1.9.3 / 193；不需要迁移或重新安装云插件。

- lint、页面结构与运行契约静态检查通过，新增检查禁止页面直接导入 dialogState。
- 仅验证纯请求协议：独立模块副本确实不共享状态，而应用入口能统一打开/读取/结算/交付；
  包含五种类型、重复请求、单次结算、请求归属、销毁取消、旧回调、导航失败和重新打开。
- 使用真实 toolkit 解析器与样式转换器验证四页，不以模拟页面显示证明原生效果。
- 不运行全量桌面模拟验收、性能基准，也不连接或部署设备。
