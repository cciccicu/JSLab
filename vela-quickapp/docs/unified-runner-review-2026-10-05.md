# 统一运行器与云插件深度复查

日期：2026-10-05。范围是本次统一运行器改动、原有 UI/Console 优化、内部页面调用、文档/类型/提示词、云空间/市场链路、数据库升级及当前诊断工具。以[已确认方案](unified-runner-plan-2026-10-05.md)为行为基准；[首次实施报告](unified-runner-implementation-2026-10-05.md)作为此前构建记录保留。

复查结论：单运行器方向和模块边界合理，可以保留。首次实现还有真实遗漏，已修复下面列出的项目；不能只凭此前构建通过认定全部边界完成。

部署约束已按用户补充确认：云插件覆盖后通过 **PM2 重启整个进程**。因此无需假设旧实例热更新后继续回调，本次去掉针对该假设加入的请求管理器和测试。保留启动时恢复中断预留额度及正常请求的原生超时。应用版本保持 **1.9.3 / 193**，云插件保持 **0.5.1**。

## 架构判断

| 模块 | 所有权与职责 | 判断 |
| --- | --- | --- |
| app.ux | 编辑器状态、一次性运行源码、对话框请求入口 | 只交接名字/源码，不保留运行闭包；适合继续保持简单 |
| run.ux | 本页源码执行、UI/Console 目标视图、原生页面导航、日志发布、错误摘要 | 页面生命周期和显示相关逻辑集中在页面，避免新增执行器服务层或双模式分支 |
| uiRuntime.js | 定义/帧/signal/回调、合并刷新、可见性、显式提交回退 | 普通 JS 会话隔离正确；失败回退只服务显式提交，正常更新成本不因此扩大 |
| uiLayout.js | 布局编译、预算、稳定身份、叶子与网格缓存 | 不处理日志、路由或弹窗；浅层绘制节点和缓存快照继续复用 |
| uiPublisher.js | 编译快照到页面字段更新 | 不读取响应式树做深比较，不引入 splice 和2048专用路径 |
| consoleBuffer.js | 本次日志、有限预览与错误格式化 | UI可见时只缓存日志，不发布隐藏text；与编译器解耦 |
| scriptRuntimeApi/scriptData/scriptDialogApi | 系统能力、文件命名空间存储、脚本对话框入口 | 按能力划分清楚；不新增 mode/stop/onDispose 等重复概念 |
| dialogState + overlay 页面 | 请求归属与 Promise 结算；原生输入与校验 | 函数/大文本/完整选项不进入响应式数据；四个浅层页面共享样式，不为一致性增加递归组件 |
| 云 index/browser-pages | 生命周期/API/审核/计费；SSR 网页 | 保留现有紧凑结构。未将每条路由拆成独立文件，也未添加网页框架 |
| 云 persistent-state/unified-migration | 幂等持久化初始化；事务迁移 | 同时覆盖安装、更新只boot、重复启动。无需版本注册表或 install 重跑假设 |

依赖方向仍是页面 → 会话 → 编译/发布；脚本 API → 能力模块；overlay → 对话框状态。不存在旧 Console/UI 两套实际执行入口。没有新建通用任务管理器、手势识别器、路由状态机或兼容执行模式层。

## 数据与更新路径

实际 boot 顺序：登记持久化配置/补建表 → 事务移除 type/pending_type，并按需添加审核内容关联字段 → 恢复进程中断的 reserved 额度 → 注册路由/页面/导航。PM2 启动后不要求用户重新 install。

- 脚本与市场的 ID、归属、名字、源码、hash/checksum、时间、发布状态和待审副本不重写。
- 原生 DROP COLUMN 保留已有索引、唯一约束和自增高水位；重复迁移不会重建已有表。
- 已有 .ui.js 文件继续作为普通 .js 身份，本地 script.data/config 仍使用原文件名，不做批量重命名或存储搬家。
- moderation_reviews.content_hash 为可空新增字段。旧记录和理由保留，NULL 不作为当前内容的审核依据；新记录明确关联被审内容。
- 启动恢复只处理 reserved 记录，在事务中置 cancelled 并退回额度；下次启动不会重复退款。
- 已保存的 API 密钥、模型与价格等配置由宿主 register 的幂等默认值登记机制保留，未显式调用 config.set 覆盖它们。
- 原始 SQLite 模式检查覆盖本仓库上一版结构及缺失辅助表的情况；不宣称能自动修复任意手工损坏或更早的未知数据库结构。宿主仍需 SQLite≥3.35。

## 全局一致性与残留检查

新建、模板、三个编辑器、运行入口、云列表、市场发布/待审/下载/保存、管理页、AI 请求/提示词、API 文档/类型与内置帮助统一采用同一脚本能力。所有系统 API 保持原生回调语义；对话框采用 action/value，不混用旧布尔或数组下标结果。

生产源码没有旧 run-ui/run-console 页面、executionMode、后缀分流、运行菜单或旧对话框回调接口。搜索中的 .ui.js 是现有文件身份说明；提示词中的旧 API 名称是禁止生成清单；迁移中的旧列名用于删除，均具有明确用途。

历史性能数据、字符串样式fixture、原始诊断引擎和旧Git比较保留历史含义。当前诊断同步明确读取 run.ux，优化快照已刷新；原始测量基线的文件及模板哈希不修改。历史审查文档不冒充当前 API。

Console 使用内容区原生 click；点击/滑动、惯性、事件分发、控件和滚动行为仍交给 Vela。导航只保留 JSLab 自身必要的目标视图和 pending 动作。
