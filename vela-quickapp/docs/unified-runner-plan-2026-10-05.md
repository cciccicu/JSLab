## 一、最终目标与范围

JSLab 只有一种 JavaScript 脚本和一个运行器。Console 与 UI 是同一次执行的两个展示视图；文件名不决定能力、API、AI 提示词或云端分类。

本次以统一行为、接口命名和视觉规则为优先，不维护旧脚本接口兼容层。保留用户文件、持久化数据、云文件和市场记录，不自动改写已有源码或强制重命名。

实现原则补充：优先直接使用 Vela 原生组件、事件和生命周期。平台已经负责的点击/滑动区分、惯性滚动、事件派发、滚动边界、原生控件状态与页面导航，不再用 JS 重复实现。仅保留 JSLab 自身的视图选择、日志缓冲、源码传递、结果模型和必要业务校验；只有确认原生能力确实缺失且影响实际需求时，才做局部补充，不为假设中的异常预设兜底系统。

明确保留的运行器操作：

- 左上返回与系统返回：UI → Console → 调用方页面。
- 右上重载：销毁并重新创建运行页，重新执行本次源码。
- Console 正文轻点：存在已成功提交的 UI 时，执行与 ui.show() 相同的动作。
- 脚本可主动显示/隐藏 UI、完整重载和退出。

明确不实现：运行菜单、停止按钮、script.stop、原页面实例内重跑、公共清理登记 API、通用任务托管、多字段表单、任意布局对话框和嵌套弹窗系统。

工作范围覆盖 Vela 运行页与入口、共享 UI 引擎和控件细节、应用内部与脚本共用的对话框、新建/编辑/模板、文档和类型、AI 生成请求与提示词、云空间和市场的 API/数据/网页，以及配套传输链路的联动验证。

## 二、核对现状后确认的联动点

| 当前实现 | 这次必须处理的影响 |
| --- | --- |
| executionMode 根据 .ui.js 分流；新建页、编辑器和模板也区分模式 | 不能只合并运行页；入口、命名和帮助必须同时去掉模式概念 |
| 两个运行页独立执行 Function，Console/UI 注入对象不同 | 合为一个执行入口，避免跳转重跑、状态丢失和错误语义分叉 |
| Console 缓冲在模块层，只有同步异常捕获，格式化后才截断 | 改为本次页面的有界日志；统一可捕获的异常入口；限制前置格式化 |
| 对话框直接把带 callbacks 的全局 request 放入页面数据 | 分开普通显示数据与函数/Promise，避免回调进入响应式观察 |
| 数字框把初值取整并只允许非负数，字符串选项同时承担显示和值 | 标准输入、值类型、校验和结果模型重新统一 |
| 确认框固定“确认/拒绝”，编辑器依赖确认、拒绝、取消三条路径 | 新接口必须表达三个明确动作，不能把“不保存”误当作“继续编辑” |
| 文本输入已有较长用途，例如 AI 需求允许 4000 字符 | 完善输入不能把所有输入强制缩成几十字，也不能把全文反复铺到原生 text |
| 云 AI 提示词按后缀禁止另一类 API；运行信息仍有旧执行器/版本默认值 | 重写统一运行契约、环境字段和生成示例 |
| 云 scripts、market_scripts 及待审核副本保存 type/pending_type | API、数据库、市场发布、审核和网页不能继续依赖旧类型 |
| AstroBox 文件选择目前本来按 .js 处理，桥接转发请求内容 | 核对即可；没有证据要求为了运行器合并重做传输协议 |

## 三、统一运行模型与 API

所有 .js 文件进入同一路由，建议 /workspace/run。删除两个旧执行器及其分流工具，避免保留两套实际运行逻辑。

旧 name.ui.js 仍是普通 .js 文件：不提供特殊能力、不自动创建这种后缀，也不为了删除模式而批量更名。script.data/config 的命名空间继续根据实际文件名确定，避免同名碰撞和数据丢失。

每次页面实例拥有一份固定的启动信息：文件名与源码快照。源码可以是编辑器尚未保存的内容。执行一次后，UI/Console 切换、打开对话框和页面 onShow 都不再执行脚本。

统一注入 console、ui、dialog、script、system。删除 script.mode。现有 UI 组件、布局、颜色能力由同一套实现提供，不用兼容分支模拟旧双模式。

| 操作 | 约定 |
| --- | --- |
| ui.render(view) | 校验、编译并提交界面；成功后请求显示 UI。显式 render 总有相同含义，不区分“第一次特权” |
| ui.show() | 显示已提交的 UI，应用隐藏期间的最新状态；无有效 UI 时返回 false |
| ui.hide() | 显示 Console，保留本次运行、日志、UI 定义和状态；重复调用无额外效果 |
| ui.refresh / signal.set/update | 更新现有界面；不改变当前主视图，不抢对话框焦点 |
| script.reload() | 与右上按钮共用完整页面重建逻辑 |
| script.exit() | 离开整个运行器，返回调用方；从 UI 也可以一步退出 |
| console.log/info/warn/error/clear | 同一有界日志缓冲；error 是日志级别，不自动停止或切屏 |

不同时提供 ui.exit 与 ui.hide、script.showConsole 等重复入口。不增加 script.showMenu、script.stop、script.onDispose。

创建 signal、构造节点、设置标题/顶栏不单独切换视图。错误的首次 render 不设置“可返回 UI”；先前已有成功画面时，新的失败保留它。空界面 ui.render([]) 是合法提交，应显示明确的空界面状态。

初始逻辑视图是 Console。首段代码立即提交 UI 时，让页面的初始展示直接呈现已选择的视图，不人为插入一帧日志页或额外延时。异步等待后才 render 的脚本，可以先正常显示日志。

切换方法完成的是状态/宿主提交请求，不承诺屏幕已经完成绘制。运行页不伪造“所有任务已完成”或提供无法覆盖原生任务的停止状态；同步主体返回与页面生命期分开。

## 四、点击 Console 返回 UI

条件使用“本次运行至少有一次成功提交的 UI”，而不是只检查脚本是否曾进入过 render 函数。

- 日志正文及其空白内容区域轻点时，复用 ui.show 的内部动作。
- 有可恢复 UI 时，显示简短提示“轻点日志返回界面”；没有 UI 则不显示这项提示，点击也不做额外动作。
- 只在 Console 正文容器绑定原生 click；顶栏、返回、重载作为独立区域，不把点击处理器挂到整个页面根节点。
- 点击与滑动的区分、惯性滚动和事件派发交由 Vela；不增加 touchstart/move/end 坐标跟踪、移动阈值、惯性检测、点击冷却或防穿透状态机。
- 恢复 UI 不重跑代码，保留 signal、回调、标题和全屏偏好。滚动边界使用原生处理；只有内容树重建确需恢复阅读位置时才保存必要偏移并调用原生滚动接口，不自行模拟滚动。
- 控件动画、原生按压状态不作为必须保存的数据；逻辑值由脚本状态恢复。

这使用户可以通过“UI 返回 → 查看日志 → 轻点日志”形成简单往返，无需菜单或额外恢复按钮。

## 五、返回、顶栏与完整重载

| 场景 | 左上/系统返回 | 右上 |
| --- | --- | --- |
| Console | 离开运行器 | 完整重载 |
| 有顶栏的 UI | 回到 Console | 完整重载 |
| 全屏 UI | 系统返回进入 Console；脚本可自带 ui.hide/exit 控件 | 跟随顶栏隐藏，脚本可调用 reload |
| 对话框 | 取消本次对话框，回到来源视图 | 确认本次输入等对话框主操作，不是重载 |

统一的是同类页面的角色和行为，不把对话框确认图标改成重载。ui.showHeader(false) 只控制 UI 顶栏，Console 总能提供返回和重载。

重载采用本次执行的源码快照，不悄悄改为重新读取磁盘文件，也不依赖之后可能变化的 editor 全局对象。要运行编辑后的代码，应返回编辑器再次运行。

完整流程：

1. 按钮与 script.reload 进入同一处理器，立即防止重复触发。
2. 准备一次性启动信息，只包含名字/源码等必要数据，不携带旧 UI 闭包。
3. replace 当前运行页，新实例读取并消费启动信息，初始化日志、UI、错误、滚动和宿主数据。
4. 新实例执行源码一次。旧实例不能继续更新新实例。
5. 导航失败时，保留当前页并显示错误，不假装已经成功重载。

直接使用 Vela 原生 replace 与页面生命周期完成重建，不预置中转页、手工路由栈或导航轮询。验收确认旧实例销毁、新实例执行一次；只有实际复现平台未按文档重建的情况，才针对该问题调整。

对话框存在时，reload/exit 不能只替换最顶层对话框、把旧运行页留在栈里。统一导航入口记录一个待执行动作，先关闭归属于本页的对话框，再对恢复的运行页执行替换/退出；不扩展成通用任务队列。

页面重载不等于重启应用 JS Context。保留页面初始化、释放宿主引用、失效检查等必要工作，不承诺自动清除任意模块全局、音频或系统订阅，也不新增清理框架。同步死循环仍无法由按钮抢占。

## 六、日志与错误体验

建议日志预算：最多 64 条、合计 6144 字符、单条最多 1024 字符。保留最近内容，超限逐条淘汰最旧记录，并显示省略计数。这里是字符预算，不再在提示词里误写为 6144 bytes。

- 控制对象预览的总元素数、层级和文本量，不先无限 JSON.stringify 再截断。
- 空字符串、换行、多参数、Error、null、循环引用都给出稳定且有界的展示。
- UI 显示时只记录 JS 缓冲，不更新隐藏的日志 text，也不安排其 flush timer。
- Console 可见时沿用合并刷新，避免每条日志单独穿过响应式桥接；进入 Console 立即同步一次。
- 阅读日志采用原生 scroll 行为，默认不在每次日志更新后强制 scrollTo，也不另做惯性检测、滚动锚点补偿或自动跟随状态机。
- ui.hide/show、点击日志及对话框开关保留日志；reload 开新记录，exit 释放记录。
- 不自动写文件，不加入日志导出流程或后台长期保存。

错误使用同一个限长格式化入口，处理字符串、null、普通 Error 和转换失败。错误前日志继续可见；运行器额外保留最后一个错误摘要，避免被普通日志淘汰掩盖。

编译/顶层同步错误、顶层返回 thenable 的拒绝、UI 回调和 UI 编译/提交错误使用同一报告机制。对任意未返回 Promise 链及原生回调，不因合并而宣称全面拦截；不为捕获它们代理全部原生 API 或包管全部计时器。

已有 UI 时保留上一幅有效画面与可见错误提示，返回可查看日志；没有 UI 时直接在 Console 展示。全屏下错误仍能读到，但不新增运行菜单或抢回另一视图的按钮。普通刷新不自动抹掉错误；明确的新 render、后续用户控件操作或重载可按一致规则清除当前提示，日志记录仍保留。

## 七、UI 引擎与视觉细节整理

沿用已优化的编译缓存、稳定节点身份、对象样式和字段发布。此次合并不改用 splice、不深比较整个响应式树，也不增加 2048 专用路径。

可见性处理：

- 主模板按视图条件挂载 UI 或 Console，不仅用 show 留下两棵原生树。
- UI 隐藏或被输入对话框遮住时，普通 signal 刷新只记录 dirty；恢复后合并处理最新状态。
- 显式 render 仍校验定义并保留及时的错误反馈；对话框不会因此关闭，背后的目标视图可记录到返回时呈现。
- 挂载/卸载时显式同步发布器状态，避免返回后因“没有变化”而不恢复节点。
- 标题、顶栏可见性和布局起点按视图区分，不能把全屏 UI 的 12px 起点套给 Console；原生组件能够保留的滚动/控件状态不再复制一份 JS 状态。

视觉和组件复查包括：

- 336×480、324px 内容宽、102px 顶栏、72px 顶栏触控区域统一；全屏 UI 保持现有内容边距。
- 统一宿主背景、卡片、主次文字、错误与禁用视觉；保留脚本自定义颜色的完整能力。
- 统一标题长度策略与长标题展示，清理相邻页面字号/留白无缘由的差异。
- 长正文可滚动；按钮短文案有明确换行/裁剪规则；错误卡片不挤掉退出路径。
- 检查 scroll 内 shrink、底部安全距离和控件命中区域；动态内容收缩后的滚动边界由原生组件处理，不重复钳制。
- 增加轻量的 ui.button disabled 状态，优先映射原生禁用能力；自绘声明式按钮仅保留实现该语义所需的点击入口检查。开关/滑块直接遵循原生交互，不增加手动状态复位或通用事件代理。
- 清理与旧双模式绑定的接口别名和文案；既有有效布局能力不因整理被重写成新的 DSL。

只有明确改善可用性、可低成本实现的项进入这一轮。不增加精确字体测量、通用动画系统或对所有原生控件状态的回滚机制。

## 八、标准对话框的统一 API

范围为单项文本、单项数字、单选/多选、确认与信息提示，不做多字段表单和任意 UI 组件树。

保留清楚的类型方法：

| 方法 | 作用与主要参数 |
| --- | --- |
| dialog.alert | 信息提示，一个主要确认动作 |
| dialog.confirm | 确认操作，可选第二业务动作，用于“保存/不保存/继续编辑” |
| dialog.text | 文本输入：value、placeholder、required、minLength、maxLength、初始语言 |
| dialog.number | 数值输入：value、required、min、max、decimals，可输入负数和小数 |
| dialog.select | 选择：items、value、multiple、minSelected、maxSelected |

公共参数统一为 title、message、confirmText、cancelText；confirm 可加 secondaryText；必要的危险操作使用一致的语义样式。初始输入一律用 value，选项集合一律用 items，不再混用 initialValue/options 等名称。

所有方法返回 Promise，结果统一为：

```js
{ action: 'confirm' | 'secondary' | 'cancel', value: ... }
```

- text 确认时 value 为 string；number 确认时为有限 number，允许空且未填写时为 null。
- select 单选时为选项值，多选时为按 items 顺序排列的值数组。
- alert/confirm 没有输入数据，value 为 null，通过 action 判断所选动作。
- 用户返回或取消始终 action: 'cancel', value: null。空文本、数值 0、选项 false 与取消不会混淆。
- secondary 仅在配置了第二业务动作时出现。没有隐含的“拒绝 = 返回 = false”。
- 参数无效、已有对话框、无法打开等是带稳定 code 的 rejected Error；正常取消不是异常。

不保留旧 Promise<string|null>/boolean|null 与新结果并存的分支。脚本示例和所有应用内部调用同步改用新结果。

例如：

```js
async function main() {
  const result = await dialog.number({
    title: '目标温度',
    message: '允许负数，保留一位小数',
    value: -2.5,
    min: -20,
    max: 50,
    decimals: 1,
    confirmText: '应用'
  });
  if (result.action === 'confirm') console.log(result.value);
}
main().catch(error => console.error(error));
```

await 置于 async 函数中，普通脚本顶层不自动获得顶层 await。

## 九、对话框的功能和交互细节

### 文本输入

- 复用 Vela 与现有输入法提供的输入、焦点、候选/组合和编辑行为，只统一调用参数与结果，不在对话框外另写一层输入事件处理系统。
- 中间位置编辑优先使用现有组件能力；仅对确认缺失的必要功能做低成本补充，不另建通用光标/选区引擎。
- 默认长度适合短输入，同时允许较大的明确 maxLength。统一硬上限建议 8000 字符，覆盖现有 AI 需求 4000 字符的用途；显示仅使用有限窗口和字符计数。
- required、minLength/maxLength 的反馈靠近输入区；不默默裁切合法初始内容来掩盖超限问题，不自动 trim 所有输入。
- 输入法的组合/候选上限与目标字段 maxLength 分开。当前组件 maxlength=5 不直接等于最终只能输入 5 字，不能把它误改成随全文长度创建数千个候选槽位。
- 每次输入只更新必要的值、显示片段、计数与校验；不重建输入法，不重新挂载整页，不复制组件已经管理的编辑状态。

### 数字输入

- 输入过程中保存字符串，允许空、负号、末尾小数点等中间状态，确认时再转换为数值。
- 不再 Math.round 初值，也不再 parseInt 静默吞掉小数；非法或超范围输入明确提示，不自动夹紧成另一个值。
- 根据 min/max 与 decimals 决定符号键、小数点的可用性；decimals=0 时明确为整数输入。
- 保留退格，提供可发现的清空；初值首次输入替换与用户后续编辑的规则统一。
- 设置合理的输入位数/精度上限，使用整数位数约束避免无意义浮点溢出；不实现任意精度运算或科学表达式解析。

### 选择框

- items 统一为 `{ label, value, description?, disabled? }`，不再用显示文字作为业务 ID。
- value 只接受 string、有限 number 或 boolean，要求唯一；禁用项不能提交，理由可由 description 展示。
- 单选点击改变选中状态，确认后提交；多选显示选择数量，支持数量约束，空选择是否有效由 minSelected 决定。
- 选择项使用原生列表连续滚动，总量不超过 100 项；不提供点击分页，滚动交给 Vela 原生组件。
- 标准单选标记与多选标记区分，选中状态不能只靠颜色表达。
- 无选项、全部禁用、初值失效和选择数不足都有明确反馈，不把“没有选择”静默当作取消。

### 确认、信息与视觉一致性

- 编辑器离开提示使用可读按钮文字“保存”“不保存”“继续编辑”，不要求用户读说明来推断“确认/拒绝”的含义。
- alert 一个主动作；confirm 按需要显示两个或三个明确动作，不强制每个简单提示都占满三按钮。
- 标题、说明、错误、触控区域、按钮尺寸和危险样式由同一组宿主规则定义。
- 长说明滚动，操作区固定且不遮挡内容；单行与多行标题采用同一策略。
- 输入类保留顶栏确认以适应键盘空间。文本键盘现为 255px 高，102px 顶栏与键盘之间约 123px 用于输入、必要说明和错误；不再叠加一排固定底部大按钮造成拥挤。
- 确认/信息页没有键盘，可使用清晰的文字按钮和独立可滚动正文。统一语义，不强求所有类型具有完全相同的空间排布。
- 检查低对比、错误覆盖键盘、底部按键越界、长标签截断和多次点击确认的问题。

## 十、对话框实现方式与全应用迁移

继续使用少量浅层原生页面，复用外壳、校验和结果交付逻辑。文本输入法只在文本页构造，数字/确认/选择不挂载它。不要为了代码表面统一，把所有类型变成常驻的大型动态表单树。

对话框控制器只保留一个当前请求。普通显示参数与 resolve/reject/来源页面引用分离，函数不进入响应式页面数据。没有嵌套、自动排队或通用异步任务注册。

结果交付与 Vela 的原生返回/页面恢复生命周期衔接，保证每个请求只结算一次，连续 await 对话框不会相互误关闭。仅处理这项 JSLab Promise 与页面之间的衔接，不用延时猜测“导航稳定”，也不建立自定义导航完成检测或路由状态机。正常返回保留来源视图；来源已经退出或被重载则释放旧归属，并按约定结束 Promise。

应用内部与脚本 API 共用同一个服务与结果规则，迁移范围包括：

- 首页相关删除/确认。
- 主编辑器与 v0/v1 编辑器的保存离开、另存为等。
- AI 生成方式与需求输入。
- 编辑器设置、字体/高亮数值和预设选择。
- 云连接方式、解除配对、云文件改名/覆盖/删除。
- 市场搜索与下载覆盖确认。

连同宿主错误和成功提示的文案一起检查，避免输入框已经统一，调用方却继续解释旧的 true/false/null 或按显示文字推断业务值。

## 十一、新建、编辑器与示例

- 新建页只输入文件名和选择模板，默认 .js，删除 Console/UI 选择器。
- 模板合为一份集合，可按用途分组：日志、界面、输入、网络、游戏。分组只帮助查找，不决定运行方式。
- 编辑器删除“切换执行模式”和自动补 .ui.js 的逻辑；另存为按统一 .js 规则处理。
- 运行总是使用当前编辑内容，不要求先落盘；重载使用本次运行快照。
- 2048 保留经典颜色与十字方向键，补充适当的日志与全屏返回示例；游戏“新局”仍是游戏自身状态操作，不等于运行器重载。
- 示例覆盖纯日志、UI+日志、全屏显示/隐藏、对话框结果、负数小数、多选以及完整重载。
- 原有数据存储、安全校验和文件名合法性规则继续适用，不以统一脚本为由搬迁用户数据。

## 十二、文档、类型与 AI 提示词

建立一份当前运行契约，明确对象、方法、结果、限额和交互规则。固定常量与公共名称用一份小型结构化描述进行构建期同步/校验；解释性文档和示例人工维护，不生成运行器代码，不把文档解析放到设备执行路径。

更新对象包括根/快应用/云插件 README、当前 UI 文档、统一脚本 API 文档、类型声明、内置帮助、模板和云端 AI 参考内容。旧历史审查/性能记录保留其历史事实，并与当前规范区分；不把所有历史 .ui.js 字样机械删除。

AI 系统提示词整体整理，而不是仅去掉几句禁止项：

- 删除文件名决定模式、UI 禁止 console、普通 JS 禁止 ui、script.mode 等规则。
- 所有脚本具备同一能力，由实际任务决定是否构造界面；不强迫每个脚本 render，也不强迫只输出日志。
- 写清 ui.show/hide、点击 Console、返回层级、右上重载和全屏行为。
- 使用新的对话框参数与 action/value 结果，生成取消/无效输入处理，不猜测布尔返回或字符串下标。
- 删除过时的示例、重复句、旧 appVersion/editorVersion 默认值和虚构 API。
- Console 限制按字符表达；源码上限按 UTF-8 bytes 表达；UI 声明节点与展开绘制节点分开描述。
- 避免在初始化或 finally 自动 exit/reload；渲染函数保持纯函数；网络任务仍按真实系统 API 的回调语义编写。
- 不生成 script.stop、onDispose、运行菜单或其他已经排除的接口。
- 生成结果语法验证以 Function 函数体语义为准，不误允许顶层 await；服务端只解析检查，不执行生成代码。

在测试中检查提示词引用的方法确实存在、固定限制一致、示例使用当前结果模型。不能把这些检查说成 LLM 一定不会生成错误代码。

## 十三、云端接口、数据与网页

### 统一脚本数据模型

移除脚本执行类型这一业务概念：

- 云脚本创建/更新不再根据后缀推断 ui/console，响应不再返回该 type。
- 市场发布/编辑删除 marketType 必填项；列表、详情、作者页、管理/审核页不再展示或筛选 UI/控制台类型。
- 待审核更新、审核通过、撤回草稿、市场下载和保存到云空间都使用同一结构。
- 用途标签仍可保留，例如工具、游戏，它们不控制执行器。
- 设备云文件列表不再读取 type 生成显示文案；网页渐进脚本也删除对应表单取值与自动填充。

数据库中 scripts.type、market_scripts.type、market_scripts.pending_type 应通过一次可重复执行的数据迁移移除，不把它们改成没有意义的固定值再长期维护。

迁移保留 ID、归属、文件名、源码、hash/checksum、时间、发布/待审状态和其他业务信息。使用宿主实际支持的 SQLite 迁移方式；若需重建表，则事务内复制并保留索引/自增行为。用历史数据样本测试首次与重复迁移，不仅测试空库 CREATE TABLE。

不自动重命名 name.ui.js、不改写其内容或 hash。文件名仅按普通 .js 文件名校验，云文件和本地持久化数据不会因去掉类型而变更身份。

### AI 契约同步与同版本覆盖

包版本号不能可靠区分这次运行契约，因为用户允许同版本覆盖安装。增加一个明确的运行契约标识，例如 `runtimeContract: 'jslab-unified'`，用于设备与云端 AI 请求确认，属于协议能力标识，不递增应用版本。

- 云端在已有能力/额度信息响应中公布支持的运行契约。
- 新设备在提交收费生成请求前确认支持；不支持则明确提示需要同步更新，避免请求旧提示词生成后才发现代码不可运行。
- 云端在调用模型和预留/扣费前检查请求契约；不维护旧双模式提示词分支。
- 生成结果携带对应契约，设备确认后再写入编辑器。
- 直连 fetch 与 AstroBox 桥接都传递同一字段，不根据传输方式改变可用脚本 API。
- 现有 create/rewrite 是 AI 工作方式，与 Console/UI 执行类型无关，保留其含义及计费用途。

代码生成提示词和市场审核提示词职责分开。审核不再把 console 与 ui 混用当作模式错误，也不能仅凭 .ui.js 或 type 推断脚本能力；原有发布审核流程继续正确处理待审源码。

### 网页与配套端

云网页沿用 ccicc.icu 的 SSR、Bootstrap 和宿主设计规则，统一术语、按钮意义、输入错误与空状态；不把手环的固定像素布局搬到网页，也不新建 SPA 或另一套主题。

AstroBox 插件重点核对 .js 上传/下载/编辑、新建文件和 cloudProxy 能否原样承载新请求及结果。当前已按 .js 处理，若透传足够，只调整相关说明和验证，不改 WIT 或消息协议版本来制造无关升级。Lua 表盘/字体链路不参与运行器合并。

云端发布涉及真实数据库和服务，实施阶段先产出可审查的迁移与安装包；本方案本身不执行在线部署。

## 十四、改动落点与实施顺序

| 顺序 | 主要落点 | 完成标准 |
| --- | --- | --- |
| 1. 契约与清单 | 当前方案、统一 API/类型、运行常量 | API、对话框结果、导航、云字段和限额不矛盾 |
| 2. 单一执行器 | app.ux、manifest、routeManager、run 页面、runtime 工具 | 一次执行、两种视图、轻点恢复、完整重载、返回层级工作 |
| 3. 对话框与宿主调用 | scriptDialogApi、dialogState/服务、原生对话框页、所有 openDialog 调用点 | 单一结果模型、输入能力完善、关闭时序稳定、内部页面同步迁移 |
| 4. 入口与 UI 整理 | 新建、编辑器、设置、模板、2048、共享样式和受影响控件 | 没有执行模式入口，视觉和交互细节一致 |
| 5. 云端联动 | cloudService、AI 页面、index.js、browser-pages.js、网页脚本、ai-prompts.js | 类型迁移和全部 CRUD/发布/审核链路更新，统一 AI 契约 |
| 6. 文档与验证交付 | README、API 文档、类型、帮助、测试、主包与云插件包 | 文档反映实际实现，关键路径和性能检查通过 |

顺序表示实施依赖，不是每完成一小步就交付一个测试版本。各项目在自己的目录测试打包，产物不混用。应用及插件版本保持当前值，除非用户另行指定；主包构建前备份 dist 到其目录之外。

## 十五、验收与性能边界

桌面/模拟接口验证：

1. .js 与名为 .ui.js 的文件经过同一执行器；初始化、随机数、文件/网络副作用不会因视图切换重复发生。
2. render/show/hide、点击日志、系统返回、顶栏返回和全屏偏好遵守同一规则；失败 render 不制造可恢复的空白帧。
3. Console 正文的原生 click 正确触发 UI 恢复，顶栏操作独立；原生滚动正常，代码没有重复的触摸识别、惯性检测或滚动补偿机制。
4. 两个 reload 入口重建页面，重复点击只有一次导航；旧页销毁，新页执行一次；对话框存在时不留旧运行页。
5. 有界日志、错误前文、对象预览、非 Error 异常、thenable、隐藏视图的发布次数正确。
6. 对话框所有返回类型、三选确认、负数小数、输入中间态、必填/范围、长文本、多选/禁用/重复值和大列表限制正确。
7. 连续 await 两个对话框、返回取消、快速重复确认、来源页销毁都只交付一次结果；编辑器三个离开选项仍正确。
8. 云迁移保留已有数据，重复迁移无副作用；云 CRUD、市场待审更新/审核/下载/保存、网页填充与设备列表都不再依赖执行类型。
9. AI 能力确认发生在收费请求之前，云端契约检查发生在预留/模型调用之前；新提示词与示例不引用已删除 API。
10. API/类型/限额与提示词一致，直连及桥接的数据合同一致。

性能验证沿用已有 UI 对照和 2048 工作负载，重点检查新增分支没有引入多余节点/响应式写入。对话框不应在每个按键重建输入法、不应为一次选择重新构建所有原生选项，也不应在普通 UI 每次刷新时处理日志。

真实设备统一验证一次：2048 交互 → 返回日志 → 滚动与轻点恢复 → 全屏 → 右上重载/脚本重载；再覆盖文本长输入、负数小数、单/多选和保存离开三选确认。记录切换/重载/对话框响应，不把事件循环到达时间当作屏幕绘制完成时间。

本方案不声称已得到新的真机延迟或零开销结论。若实现出现可重复、超出测量波动的正常 UI 性能回退，应先定位额外原生发布/节点/格式化工作，不能以“统一架构”为理由接受明显变慢。
