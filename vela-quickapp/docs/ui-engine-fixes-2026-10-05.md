# UI 审查问题修复与性能验证（2026-10-05）

按用户要求，优先选择不明显影响正常刷新、无需复杂机制的修复。本次处理了审查报告中的 8 项问题，保留原有网格快速编译、节点身份、字段发布和对象样式绑定。没有增加原生组件或深比较。

**修复内容**

| 原问题 | 处理方式与成本 |
| --- | --- |
| 并发存储丢数据 | 把已有写入队列提前到读取和修改数据之前。单个脚本连续调用两次 set 即可触发旧问题，不依赖同时运行两个脚本。每次保存仍只有一次文件写入，不影响 UI 刷新路径。 |
| 无效几何 | 每个网格验证格子分配宽度，每个 row 子项验证 flex 分配宽度；不足 1px 就沿用布局错误机制。 |
| 跨类型行数缓存 | 增加组件类型判断，按实际取整后的绘制宽度估算行数，避免按钮内边距和浮点宽度造成历史相关结果。 |
| 可变文本对象缓存 | 只在缓存未命中、复制输入时检查是否有可变对象/函数；普通值继续走缓存路径。可变输入重新测量，不使用深比较或序列化。 |
| 发布失败无法重试 | 宿主接受新帧后再提交内部快照；异常后的下一次刷新强制提交，页面仅在发布异常时丢弃发布器状态。正常帧不复制额外节点，也不加入通用回滚事务。 |
| 错误提示消失 | 普通刷新保留错误卡片及高度；下一次有效控件交互、显式 ui.render 或重新运行时清除。无错误时不进行错误布局计算。 |
| 特殊字符串存储键 | 读取检查自有属性；仅 __proto__ 写入走 defineProperty，确保 JSON 克隆及重新加载后仍是正常数据键。 |
| 旧文档入口 | README 指向 UI v2，v1 文档增加历史版本说明；当前 API 文档补充布局下限和错误保留规则。 |

没有增加不可信代码沙箱、系统任务统一托管、精确字体测量或原生状态回滚框架。前次报告列出的设备待验证行为不视为已确认问题，本次没有围绕它们扩大改动。
